# РЕФАКТОРИНГ БЭМ-БЛОКОВ: Файловая структура и плоские стили

## 🎯 Цель
Преобразовать БЭМ-блоки из плоской структуры в правильную иерархическую, заменив каскадные стили на плоские селекторы.

## 📋 Предварительный анализ

### Что проверить перед рефакторингом:
1. **HTML структура** - должна быть правильной БЭМ-разметкой
2. **Каскады в стилях** - найти все вложенные селекторы
3. **Модификаторы** - определить какие нужны (_active, _inactive и т.д.)
4. **Зависимости** - какие блоки используют текущий

### Анализ блока Grid:
- Элементы: `ElementName/` (без `__`)
- Модификаторы блоков: `_modifierName/`
- Модификаторы элементов: `ElementName/_modifierName/`
- Импорты модификаторов в базовых файлах элементов

## 🛠️ Пошаговый процесс рефакторинга

### Шаг 1: Создание файловой структуры
```bash
# Для каждого элемента создать папку
mkdir ElementName/

# Для модификаторов элементов
mkdir ElementName/_modifierName/

# Для модификаторов блоков
mkdir _modifierName/
```

### Шаг 2: Разбиение SCSS файла
1. **Определить элементы и модификаторы** в текущем файле
2. **Создать отдельные файлы** для каждого элемента/модификатора
3. **Убрать каскады** - заменить на плоские селекторы или отдельные БЭМ-классы

### Шаг 3: Импорты и зависимости
1. **Добавить импорты модификаторов** в базовые файлы элементов
2. **Создать главный файл блока** с импортами всех элементов
3. **Проверить пути импортов**

### Шаг 4: Изменение кода компонентов
1. **Заменить каскадные селекторы** на новые БЭМ-классы
2. **Обновить генерацию className** - перейти на `cn()` функцию
3. **Протестировать** внешний вид и функциональность

### Шаг 5: Генерация CSS-классов с помощью cn()
**Использовать `@bem-react/classname` для безопасной генерации имен классов.**

#### Настройка:
```ts
// types.ts
import { cn } from '@bem-react/classname';

export const cnBlockName = cn('BlockName');
```

#### Примеры использования:
```tsx
// ❌ Ручная генерация (плохо)
className={`Tab-Label${isActive ? ' Tab-Label_active' : ''}`}
className="Tab-Content"

// ✅ С использованием cn() (хорошо)
className={cnTab('Label', {active: isActive})}
className={cnTab('Content')}
```

#### Преимущества cn():
- **Безопасность типов** - TypeScript проверяет имена
- **Программная генерация** - правильные БЭМ-имена гарантированы
- **Удобный API модификаторов** - `{active}` → `Tab-Label_active`
- **Самодокументируемый код** - читается как спецификация
- **Легкий рефакторинг** - изменение имени блока в одном месте

#### Ссылка на полную документацию:
`/docs/BEM/использовать cn() для className/`

## 📝 Примеры из практики

### Пример 1: Tab блок рефакторинг

#### Было (плоская структура):
```
Tab/
├── Tab.scss (88 строк, все в одном файле)
```

#### Стало (правильная БЭМ-структура):
```
Tab/
├── Tab.scss (главный файл с импортами)
├── Label/
│   ├── Tab-Label.scss
│   └── _active/
│       └── Tab-Label_active.scss
├── Content/
│   ├── Tab-Content.scss
│   ├── _active/
│   │   └── Tab-Content_active.scss
│   └── Tab-ContentButton.scss (новый класс)
└── ... другие элементы
```

#### Каскады → Плоские стили:

**❌ Каскад (плохо):**
```scss
.Tab-Content {
  .Button-Wrap {
    margin-right: 20px;
  }
}
```

**✅ Плоский стиль (хорошо):**
```scss
.Tab-ContentButton {
  margin-right: 20px;
}
```

#### Код компонента:
```tsx
// Было
<div className="Tab-Content">
  <div className="Button-Wrap">...</div>
</div>

// Стало
<div className="Tab-Content">
  <div className="Tab-ContentButton">...</div>
</div>
```

## 🔍 Проблемы и решения

### Проблема 1: Каскады с элементами других блоков
**Пример:** `.Tab-Content .Button-Wrap` - Button-Wrap из другого блока

**Решение:** Создать отдельный БЭМ-класс для контекста:
```scss
.Tab-ContentButton { /* вместо каскада */ }
```

### Проблема 2: Модификаторы inactive
**Пример:** `Tab-Label_inactive` используется только в коде

**Решение:** Убрать модификатор, сделать дефолтное состояние базовым классом:
```tsx
// Было
className={`Tab-Label Tab-Label_${isActive ? 'active' : 'inactive'}`}

// Стало
className={`Tab-Label${isActive ? ' Tab-Label_active' : ''}`}
```
